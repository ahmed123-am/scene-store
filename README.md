# SCÈNE

متجر React لمجسمات ثلاثية الأبعاد، مع Node.js API وSupabase للمنتجات والطلبات.

## التشغيل المحلي

من مجلد scene-store استخدم Node.js 24 ثم شغّل الأوامر التالية.

```powershell
npm ci
npm run api
```

في تيرمنال ثانٍ شغّل الواجهة.

```powershell
npm run dev
```

بيانات المنتجات المحلية في backend/products.json، والطلبات المحلية في backend/data/orders.sqlite.

## تجهيز Supabase

طبّق ملف supabase/migrations/202611190001_scene_store.sql من SQL Editor في مشروع Supabase.

انسخ .env.example إلى .env.local وأضف SUPABASE_URL وSUPABASE_SECRET_KEY محليًا. أضف نفس القيم إلى Environment Variables في Vercel.

شغّل الأمر التالي لنقل الكتالوج والطلبات المحلية الموجودة. إعادة تشغيله تتجاوز السجلات الموجودة.

```powershell
npm run sync:supabase
```

تُقرأ بيانات Supabase وتُحفظ الطلبات من خلال وظائف السيرفر. جداول العملاء والطلبات محمية بـRLS وصلاحيات السيرفر.

## النشر على Vercel

اربط ريبو المشروع واختر مجلد scene-store كجذر للمشروع، أو اترك الجذر الافتراضي إذا كان الريبو يحتوي المشروع مباشرة. ملف vercel.json يحدد أمر البناء ومجلد الناتج ووظائف API.

المساران المستخدمان هما GET /api/products وPOST /api/orders.

ملفات المفاتيح وقاعدة البيانات المحلية مستبعدة من Git ومن رفع Vercel.

المجموعة الحالية تحتوي صورًا مولّدة وأسعارًا تجريبية.

## إشعارات تيليجرام

أنشئ بوت من https://t.me/BotFather باستخدام `/newbot`، ثم افتح البوت من حسابك واضغط Start.
أضف `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` في متغيرات Production على Vercel ثم أعد النشر.
التوكن سري ويوضع على السيرفر فقط. لا تضفه إلى Git أو متغير يبدأ بـ`VITE_`.

يُرسل ملخص الطلب بعد حفظه، ويُتخطى الإشعار عند إعادة نفس محاولة الطلب.
الإرسال ينتظر حتى خمس ثوانٍ قبل انتهاء الطلب. فشل تيليجرام لا يلغي الطلب المحفوظ.
الإشعارات حاليًا محاولة واحدة، دون طابور لإعادة الإرسال؛ راجع جدول orders حتى عند غياب الإشعار.
فعّل إشعارات تيليجرام للمحادثة وعلى الموبايل.

## إدارة الطلبات

اللوحة متاحة على `/admin`. لتفعيلها على مشروع Supabase الحالي:

1. نفّذ محتوى `supabase/migrations/202611190002_admin_orders.sql` في SQL Editor. يضيف صلاحية تحديث عمود الحالة للسيرفر وفهارس الفرز، دون إتاحة البيانات للزوار.
2. من Supabase → Authentication → Users → Add user → Create new user، أنشئ حسابك بإيميل وكلمة مرور قوية مع تأكيد الإيميل.
3. انسخ User UID للحساب وأضفه على Vercel باسم `ADMIN_USER_ID` في Production، ثم أعد النشر. كلمة المرور تبقى في Supabase ولا تحتاج متغيرًا في Vercel.
4. افتح `/admin` وسجّل بإيميل الحساب وكلمة مروره. لا تضف حساب العملاء إلى ADMIN_USER_ID.

اللوحة تعرض 20 طلبًا في الصفحة، مع فلترة بالحالة وتفاصيل العميل وتحديث الحالة. الجلسة في Cookie من نوع HttpOnly وSameSite=Strict وSecure على Vercel، وتحتاج تسجيل دخول جديد بعد ساعة أو انتهاء التوكن. يتحقق السيرفر من هوية الحساب عبر Supabase عند كل طلب. لا تعتمد الصلاحيات على user_metadata أو على إخفاء الرابط.

الحالات: pending (جديد)، confirmed (تم التأكيد)، shipped (اتشحن)، completed (اكتمل)، cancelled (ملغي). يمكن تصحيح الحالة في أي وقت، لكن لا تُقبل كتابة فوق تحديث من جهاز آخر دون تحديث القائمة. تغيير الحالة لا يرسل إشعارًا للعميل ولا يعدّل قيمة الطلب. إدارة المنتجات ليست ضمن هذه النسخة.
