# SCÈNE

متجر React لمجسمات ثلاثية الأبعاد، مع Node.js API وSupabase للمنتجات والطلبات.

## الطلبات المخصصة والتواصل

التواصل يعرض نموذج طلب مخصص من زر «اطلب مجسم مخصوص»، مع صورة مرجعية واسم العميل ورقمه والكمية ووصف الشكل والمقاسات الاختيارية. هذا طلب مراجعة وعرض سعر، ويُوضح للعميل أن التنفيذ يبدأ بعد الاتفاق على السعر والتفاصيل.

قبل نشر هذه النسخة على مشروع موجود، نفّذ `supabase/migrations/202611190005_custom_requests.sql`. يضيف جدول `custom_requests` ودالتَي الحجز والتأكيد، ويجهّز حاوية Storage خاصة باسم `scene-custom-requests`. صور المراجع لا تُعرض في الكتالوج ولا في إشعار تيليجرام؛ المالك يشاهدها في قسم «طلبات مخصوص» بلوحة الإدارة، عبر روابط موقّعة مدتها خمس دقائق قابلة للتحديث. سياسة restrictive تمنع وصول anon وauthenticated إلى ملفات هذه الحاوية حتى عند وجود سياسات أوسع لحاويات أخرى. السيرفر يستخدم service_role للتحقق من الحساب قبل عرض التفاصيل.

لا تحتاج مفاتيح جديدة: يستخدم نفس بيانات Supabase وحساب الإدارة وتيليجرام. الإشعار يحوي رقم الطلب والكمية والوصف، والتسعير بالتواصل مع العميل. صور JPG/PNG/WebP حتى ١٥ ميجابايت تُجهّز في المتصفح إلى WebP حتى ١٫٥ ميجابايت قبل إرسالها للسيرفر. الحد هو خمس محاولات جديدة في الساعة لكل بصمة IP، والـIP يُحفظ كبصمة HMAC فقط. لا يزيد تكرار نفس محاولة الطلب من الحد، ولا يكرر الطلب أو الإشعار.

الحجز يحفظ بيانات الطلب أولًا بحالة رفع pending، ثم يرفع الصورة لمسار ثابت خاص ويؤكّد الحالة ready. لا يظهر الطلب للمالك ولا يرجع إيصال نجاح قبل اكتمال الرفع؛ يمكن إعادة نفس المحاولة بعد انقطاع الاتصال أو تعذّر الرفع. الطلبات غير المكتملة تبقى محفوظة ولا تظهر في القائمة. إرسال تيليجرام محاولة واحدة؛ فشله لا يلغي الطلب المحفوظ.

قسم الإدارة يتيح فلترة الطلبات المخصصة، عرض المرجع والتفاصيل، وتغيير الحالة بين جديد وقيد المراجعة وتم التواصل وملغي. هذا القسم منفصل عن طلبات الكتالوج، ولا يدخل في إجمالي المنتجات. الاتصال المحلي لهذا النموذج يحتاج مشروع Supabase مُجهّزًا؛ السلة العادية تستمر في دعم SQLite.

## التشغيل المحلي

من مجلد scene-store استخدم Node.js 24 ثم شغّل الأوامر التالية.

```powershell
npm ci
npm run api
```

في تيرمنال ثانٍ شغّل الواجهة.

```powershell
npm run dev
```

بيانات المنتجات المحلية في backend/products.json، والطلبات المحلية في backend/data/orders.sqlite.

## تجهيز Supabase

للمشروع الجديد، طبّق ملفات SQL الموجودة في supabase/migrations من SQL Editor بالترتيب الرقمي قبل استيراد البيانات أو النشر. للمشروع الموجود طبّق المهاجرات الجديدة فقط، بدءًا بالأقدم.

انسخ .env.example إلى .env.local وأضف SUPABASE_URL وSUPABASE_SECRET_KEY محليًا. أضف نفس القيم إلى Environment Variables في Vercel.

شغّل الأمر التالي لنقل الكتالوج والطلبات المحلية الموجودة. إعادة تشغيله تتجاوز السجلات الموجودة.

```powershell
npm run sync:supabase
```

تُقرأ بيانات Supabase وتُحفظ الطلبات من خلال وظائف السيرفر. جداول العملاء والطلبات محمية بـRLS وصلاحيات السيرفر.

## النشر على Vercel

اربط ريبو المشروع واختر مجلد scene-store كجذر للمشروع، أو اترك الجذر الافتراضي إذا كان الريبو يحتوي المشروع مباشرة. ملف vercel.json يحدد أمر البناء ومجلد الناتج ووظائف API.

المساران المستخدمان هما GET /api/products وPOST /api/orders.

ملفات المفاتيح وقاعدة البيانات المحلية مستبعدة من Git ومن رفع Vercel.

المجموعة الحالية تحتوي صورًا مولّدة وأسعارًا تجريبية.

## إشعارات تيليجرام

أنشئ بوت من https://t.me/BotFather باستخدام `/newbot`، ثم افتح البوت من حسابك واضغط Start.
أضف `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` في متغيرات Production على Vercel ثم أعد النشر.
التوكن سري ويوضع على السيرفر فقط. لا تضفه إلى Git أو متغير يبدأ بـ`VITE_`.

يُرسل ملخص الطلب بعد حفظه، ويُتخطى الإشعار عند إعادة نفس محاولة الطلب.
الإرسال ينتظر حتى خمس ثوانٍ قبل انتهاء الطلب. فشل تيليجرام لا يلغي الطلب المحفوظ.
الإشعارات حاليًا محاولة واحدة، دون طابور لإعادة الإرسال؛ راجع جدول orders حتى عند غياب الإشعار.
فعّل إشعارات تيليجرام للمحادثة وعلى الموبايل.

## إدارة الطلبات

اللوحة متاحة على `/admin`. لتفعيلها على مشروع Supabase الحالي:

1. نفّذ محتوى `supabase/migrations/202611190002_admin_orders.sql` في SQL Editor. يضيف صلاحية تحديث عمود الحالة للسيرفر وفهارس الفرز، دون إتاحة البيانات للزوار.
2. من Supabase → Authentication → Users → Add user → Create new user، أنشئ حسابك بإيميل وكلمة مرور قوية مع تأكيد الإيميل.
3. انسخ User UID للحساب وأضفه على Vercel باسم `ADMIN_USER_ID` في Production، ثم أعد النشر. كلمة المرور تبقى في Supabase ولا تحتاج متغيرًا في Vercel.
4. افتح `/admin` وسجّل بإيميل الحساب وكلمة مروره. لا تضف حساب العملاء إلى ADMIN_USER_ID.

اللوحة تعرض 20 طلبًا في الصفحة، مع فلترة بالحالة وتفاصيل العميل وتحديث الحالة. الجلسة في Cookie من نوع HttpOnly وSameSite=Strict وSecure على Vercel، وتحتاج تسجيل دخول جديد بعد ساعة أو انتهاء التوكن. يتحقق السيرفر من هوية الحساب عبر Supabase عند كل طلب. لا تعتمد الصلاحيات على user_metadata أو على إخفاء الرابط.

الحالات: pending (جديد)، confirmed (تم التأكيد)، shipped (اتشحن)، completed (اكتمل)، cancelled (ملغي). يمكن تصحيح الحالة في أي وقت، لكن لا تُقبل كتابة فوق تحديث من جهاز آخر دون تحديث القائمة. تغيير الحالة لا يرسل إشعارًا للعميل ولا يعدّل قيمة الطلب.

## سلة مشتريات متعددة المنتجات

قبل استخدام طلبات السلة، شغّل `supabase/migrations/202611190004_cart_orders.sql` في SQL Editor. يحافظ على الطلبات القديمة ويضيف قائمة `items` لكل طلب ودالة `create_scene_cart_order`. أبقِ الدالة القديمة للعملاء الذين لم يحدّثوا الصفحة بعد.

العميل يضيف حتى ٢٠ منتجًا مختلفًا وبحد أقصى ٥٠ قطعة إجمالًا، ويعدّل الكميات أو يحذف المنتجات قبل التأكيد. تحفظ السلة معرّفات المنتجات والكميات فقط في localStorage، دون بيانات العميل. تتحدث بيانات المنتجات عند فتح السلة، ويعاد التحقق من الأسعار والتوفر على السيرفر. جميع البنود تحفظ كطلب واحد أو لا يُحفظ أي منها. إعادة المحاولة بنفس المفتاح تعيد نفس الطلب، حتى لو تغير السعر أو حُذف المنتج لاحقًا. التفاصيل والأسعار وقت الشراء محفوظة في قائمة items، وتظهر في لوحة الإدارة والإيصال وإشعار تيليجرام.

التشغيل المحلي يضيف عمود items تلقائيًا إلى SQLite، ويظل استيراد البيانات القديمة إلى Supabase مدعومًا بعد تنفيذ المهاجرات. الإجمالي المعروض لا يشمل الشحن؛ يتحدد الشحن وطريقة الدفع عند التأكيد.

## إعداد قسم المنتجات

نفّذ `supabase/migrations/202611190003_admin_products.sql` مرة واحدة في SQL Editor، ثم افتح قسم المنتجات من لوحة `/admin` بنفس حساب المالك. الإعداد يضيف رقم إصدار لمنع الكتابة فوق تعديل من جهاز آخر، وصلاحية الحذف للسيرفر، وحاوية صور عامة باسم `scene-products`. لا تضف سياسات تسمح برفع صور للزوار أو المستخدمين العاديين.

القسم يتيح إضافة المنتج وتعديل اسمه وسعره وصوره وترتيبه، وإخفاءه مؤقتًا أو حذفه نهائيًا بعد التأكيد. تعرض اللوحة حتى ١٠٠٠ منتج، مع البحث والفلترة محليًا. التغييرات تظهر للزوار عند تحميل المتجر من جديد. الطلبات السابقة تحتفظ باسم المنتج وسعره وبيانات العميل بعد حذف المنتج، وتكرار محاولة طلب قديم يعيد نفس الإيصال.

رفع الصور من الجهاز يقبل JPG وPNG وWebP حتى ١٥ ميجابايت، ويجهز WebP بأبعاد قصوى ١٦٠٠ بكسل وحجم أقصى ١٫٥ ميجابايت. الملف يُرفع عند حفظ المنتج فقط عبر API المالك. يمكن استخدام رابط HTTPS بدل الرفع. عند اختيار صورة جديدة من الجهاز تُفرغ صورة العرض المجسمة القديمة؛ يمكن إدخال رابط مختلف لها قبل الحفظ. الصور المرفوعة عامة، وتبقى في Storage بعد حذف المنتج أو استبدال الصورة؛ لا تحذفها تلقائيًا لأنها قد تكون مستخدمة في منتج آخر.
